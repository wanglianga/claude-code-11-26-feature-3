# 区域急救药品库存与调拨分析（演示系统）

一个**纯前端**的区域急救药品库存与调拨分析工作台。所有库存推演、调拨候选生成、审批/签收状态迁移、
**冷链运输温度核查**均在**浏览器本地**执行，使用固定演示数据与本地事件适配器，**不连接任何真实医疗系统**，
也不做临床替代推断、不判断真实药品是否可用。

技术栈：React 18 + TypeScript（严格模式）+ Zustand 4 + Vite 5；测试：Vitest；部署：Nginx 静态托管 + Docker Compose。

4. **调拨工作台**：勾选草稿 → 整组确认（批准未出库）→ 出库（占用转在途）→ 逐批签收（实收/破损/待查）；

5. **库存与换算**：查看正式余量、批准占用、在途未来到货三列分离，以及底部「缺换算资料」专区（碘伏条目不参与推演）。
6. **盘点**：在工作台对任一点位做盘点修订，观察未确认草稿变为「盘点后失效」、已批准/在途单据变为「待复核」且数量不被静默修改。
7. **冷链核查**：进入「冷链运输核查」标签页，按第 4.3 节路径验证越界/未知区分、迟报缩小未知区间、校准重检与隔离放行闸门。

## 4. 冷链运输记录核查（签收时判断可核实越界 vs 传感器缺测）

入口：顶部「**冷链运输核查**」标签页。核查只给流程结论（待复核 / 可按流程接收），**不判断真实药品是否可用**。
固定阈值 **2–8℃**，最大可信采样间隔 **30 分钟**；时间轴统一 UTC，全部为静态演示资料，无任何网络请求。

### 4.1 计算规则（实现见 `src/domain/coldchain.ts`）

1. **去重与归一**：按「设备序号 + 上报序号」折叠完全重复；同设备同序号温度不同识别为**同序异值冲突**且全部保留；
   乱序上传按采样时间归一仅打标；窗口外读数单列，不参与连接。
2. **可信连接**：相邻读数间隔 ≤30 分钟才线性连接，线性段与阈值求交点后拆成正常/越界子段；
   间隔 >30 分钟的断联整段标记**未知（缺测）**——两次正常读数之间断联两小时，**不会**被当成两小时温度正常。
3. **不跨断联合并**：连续越界只在同设备、首尾相接的同状态段内累计为一段；未知断联与换传感器都会打断连续性，
   断联两侧的越界是两段独立确定事实；同时分别给出**连续越界、累计越界、未知时长**，不用全量平均掩盖超限。
4. **交接换传感器**：以交接记录衔接新旧设备窗口；重叠采样点温度不一致作为**重叠数据冲突单列**，不静默取舍。
5. **迟报 / 校准**：不覆盖历史，另生成新检查（CHK-2…）；**已批准处置保留原记录**，新检查不改写已批准结论。
6. **隔离闸门**：受影响批次先入隔离区，不写正式库存、不进调拨候选与缺口推演；仅当最新检查可接收并**批准放行**后，
   才逐批注入接收点可用余量。同箱多批次共享同一运输证据，时长只算一次，不按批次重复累计。

### 4.2 三个固定运输任务的实际核查结论（由引擎计算）

| 运输 | 场景设计 | 初始核查（引擎实算） | 结论 |
| --- | --- | --- | --- |
| CC-2001 → A | 同箱两批次、两次开箱、连续越上限、08:00–10:00 断联两小时、1 条完全重复、1 组同序异值、1 条乱序、1 条窗口外 | 最长连续越界 **36 分**、累计越界 36 分、未知 **120 分**、正常 84 分；同序冲突 1 组 | 待复核 |
| CC-2002 → B | 07:00 换传感器（重叠点温度一致，无冲突）；旧传感器 06:10–06:40 零点漂移高读 | 最长连续越界 **37 分**（≥30 分阈值）、未知 0 | 待复核（校准前） |
| CC-2003 → C | 06:45 换传感器，新旧设备同刻读数 5.0℃ vs 8.9℃ | 重叠数据冲突 **1 组**（越界仅 4 分，但冲突阻断） | 待复核 |

待复核阈值（`DEMO_REVIEW_RULE`）：连续越界 ≥30 分钟、累计越界 ≥60 分钟、未知 ≥60 分钟、存在数据冲突即阻断。

### 4.3 页面手工验证路径

1. 用 `planner / demo1234` 登录，进入「冷链运输核查」，默认展示 CC-2001：上方 KPI 给出连续/累计越界与未知时长，
   曲线中红色块为越界、灰色斜纹为断联未知、竖线标记两次开箱；点击任意红色越界块或冲突菱形，下方回到对应**原始读数**（含设备序号、采样/接收时间、标记、备注）。
2. **迟报缩小未知区间（规定样例）**：在 CC-2001 点「插入一条迟报读数」，系统生成 CHK-2：
   08:30 补传读数使 08:00→08:30 恢复为 30 分钟可信连接，**未知时长由 120 分缩小为 90 分、最长连续未知同步缩小**，
   可信连接增至 150 分；检查历史中 CHK-1 的 120 分原样保留。
3. **校准修订触发重新核验**：切到 CC-2002，点「应用校准修订（4 条漂移读数）」，原始读数保留并标「已被修订（原值）」、
   修订值采用，生成 CHK-2，连续/累计越界归零，结论由待复核转为**可按流程接收**；此时「批准放行」按钮才可点。
4. **隔离闸门**：批准放行前到「库存与换算」页，底部「冷链到货隔离区」中 B-CC-CAL-1 为隔离待处置、不出现在正式余量；
   在 CC-2002 点「批准放行进入可用余量」后，该批 15 单位才进入 S-B 正式库存。待复核运输的放行按钮禁用，后端 store 同样拦截。
5. **重叠冲突**：切到 CC-2003，可见 1 组重叠数据冲突且只能「复核后继续隔离」，不能放行。
6. 退出改用 `viewer / view1234` 登录，迟报、校准、处置按钮全部禁用或被提示拦截。


## 7. 边界与声明

- 本系统为隔离演示环境：数据为静态虚构数据，事件由本地适配器模拟，无任何网络请求或后端服务。
- 系统只做库存与物流维度的数量推演，**不提供临床用药建议、不做药品替代推断**。
- 候选为基于声明规则的**可行建议**，界面与文档均不宣称全局最优；最终调拨须由保障人员确认。
- 冷链核查只输出「待复核 / 可按流程接收」的流程结论与可追溯证据，**不判断真实药品是否可用**；
  传感器缺测（未知）与可核实越界严格区分，断联不被推断为温度正常，亦不跨断联拼接超限事实。
- 冷链批次在批准放行前一律隔离，不进入正式余量、不参与调拨；签收动作本身不会使货物自动可用。
